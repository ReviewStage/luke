A task is one piece of work, from the sentence that starts it to its merged pull request. It holds a plan, the agents working on it, and their pull requests.

This guide takes one task from start to merge. Before you start, finish [setup](/install#sign-in-and-set-up) so an agent and GitHub are connected. To check, open **Settings › Agents** and **Settings › Workspace**.

## Start the task

Press <kbd>⌘N</kbd> or click **New task**. Pick the repository, describe the change, and send it.

Write it as you would a GitHub issue: the outcome you want, and anything the agent can't learn from the code.

## Follow the agent

The task opens on its agent's tab, which shows each step as the agent takes it. The agent writes the task's plan on the **Overview** tab as it goes.

By default, an agent works in a cloud sandbox with its own checkout of the repository, not in your local checkout. To correct it while it works, send it a message on its tab.

## Answer in the Inbox

When the agent needs you, it posts a thread to your Inbox (<kbd>⇧⌘I</kbd>). A thread can end in a choice between options, a list of steps for you to do, or a short form.

Press <kbd>1</kbd>–<kbd>9</kbd> to choose an option, or <kbd>R</kbd> to reply.

## Review the pull request

The agent opens a pull request as you. Open it on the task's **Pull request** tab:

- **Files changed** shows the diff.
- **Chapters** splits the diff into sections, each with a summary.

Review and comment there as you would on GitHub. The agent reads new reviews and comments and answers them.

## Merge

Merge from the **Pull request** tab. If a check fails, the agent reads why, pushes a fix, and waits for the checks again.
