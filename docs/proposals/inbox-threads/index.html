Inbox items as threads

An Inbox item is one question from an agent and one answer from you. Today the pane draws it as a form inside a message: a byline nothing else in the window uses, an indented title, an outlined list of options that stays after you pick, and a thread that stops at your answer. Below: what reads as off, the chosen direction (B · Comment thread), how a row shows both unread and needs you, how you mark items read and unread (swipe included), the alternative, and the individual changes ranked by effort.

This version: swiping is two-stage (a short swipe opens a button, a long swipe does it), the read and unread actions use the standard mail icons (an open envelope to mark read, a closed one to mark unread), and the thread's bar drops Open agent: the agent's name opens its tab, as every agent name does elsewhere.

Tune the swipe:

Two states, one row

Should a needs-you item show read and unread too? Yes. The two marks answer different questions. Unread asks "what's new since I last looked?", which is what you check when you come back. Needs you asks "what do I owe an answer?", which is what you work through. A new question should catch your eye even with three older ones still waiting, and one you've read and put off shouldn't look brand new forever. Mail keeps the same two apart: unread versus flagged.

An earlier version got this wrong, in two ways. Its CSS made every needs-you row semibold, so read and unread needs-you rows looked the same. That's the "Before" grid below. And the blue dot meant "needs you", but a swipe or U flips the dot, and needs-you isn't yours to flip: it belongs to the agent, and only answering clears it.

So: the blue dot means unread, and needs you gets the app's attention mark. A swipe, the hover button, U, and Mark all as read all act on the dot, exactly as in Mail. Needs you becomes the orange "!" disc (attention-mark.tsx), which the window already uses for "something wants your hand". It sits beside the row's time, where a task row already wears it for a repository of another workspace (.task-mark-attention).

The recommended rows, every combination

Marking read and unread

Swipe right: a little opens, a lot does itUpdated

Mail's two-stage swipe. Drag a row right, or two-finger swipe right on the trackpad:

A short swipe (past about 24px) and letting go leaves the row resting open on a blue Read or Unread button. Click it to flip the dot; click anywhere else, swipe back, or open another row and it closes. Nothing happens by accident: a nudge only shows you the action.

A long swipe (past about 60% of the row) brightens the button, its label jumps to ride along the row's edge, and letting go flips the dot straight away, with no click. Drag back under the line before letting go and it settles open instead. The row springs back on transform alone, as DESIGN.md requires. Swiping left does nothing for now: an item has nothing safe to throw away, and an Archive would be its own decision.

Try both on these two rows:

Opening marks it read

Opening an item marks it read. Anything new in the thread later (the agent's reply, a withdrawal, a repost under its key) makes it unread again. The attention mark is untouched: only answering clears it.

Hover button

On hover, the row's time and attention mark give way to one button, Mark as read (open envelope) or Mark as unread (closed envelope), as Pin and Archive take a sidebar row's time slot today.

Right-click

The row's menu, which today holds Copy link, gains Mark as read / Mark as unread at the top, with its key beside it.

U toggles

A plain U toggles the open item, next to the Inbox's existing J/K, which are plain letters too. (⇧⌘U is taken by Automations.) Marking the open item unread keeps it on screen in the unread look until you move off it.

From the threadUpdated

The thread's bar holds the crumbs, the same envelope toggle, and the "3 of 9" count, nothing else. Open agent is gone: the agent's name in the crumbs and on its comments opens its tab, the way an agent's name does everywhere else in the window, and the settled thread ends in "Continue in agent".

Mark all as read

The list's view-options menu, under the grouping choices, gets Mark all as read. It clears the blue dots only; every attention mark stays.

The changes, one at a time

Size is a rough PR size. "Data" says whether the desktop already holds what it needs or the service has to send more.

Suggested order

  1. The comment thread (1, 2, 3): one comment layout with a thread line, the subject header with a bar that drops Open agent, and the options folded once answered with the pick as a chip. Desktop only.
  2. Thread rows: the attention mark for needs you, the blue dot for unread (5), then marking read and unread (10). The attention mark and the preview are desktop only. Read status needs the seen marker per item. Swipe comes last: the hover button, the menu, and U cover it first.
  3. The agent's reply after yours (4), then earlier context (6). These make it actually feel like a thread. They need the agent's transcript read for the item's agent, which the agent tab already does.
  4. One card in both places (8). The agent tab draws the Inbox's card where it now draws the post_to_inbox row, so the item looks the same wherever you meet it.
