Plain links and URLs

Dean: "I don't really like the style of plain URLs." Recognised links (plans and sections, repository files and lines, Linear, GitHub, Sentry and other integration pages) are becoming mention chips. This show is about everything else: unknown pages, docs, and bare https://… text. Every frame is main's compiled desktop stylesheet, in its light and dark appearance, over the DOM that the real components drew for the same synthetic words. Those components are TranscriptWords, MarkdownMessage, TipTap's editor and the mention chip. Only the inbox's link blocks and the states rows are hand-written, with the components' own classes.

Pick: (c): one quiet underline in the text's own colour for every renderer, brightening on hover. A bare URL shortens to domain/path with a small ↗, and the full address shows on hover. Rationale and build size ↓

Today, on main

Six surfaces draw plain links in three different ways:

  1. Two colours.
    • In transcripts and the Inbox, a link is .agent-link: --state-working, Luke's cyan (#5cd5ff dark, #0a72a8 light), with a full-strength underline 2px below.
    • In the plan, version history and Code-tab notes (.markdown-link) and in the editor (.plan-document-text a), a link is in the text colour, with a 28%-strength underline 0.15em below.
  2. The cyan is the voice's colour (--voice-luke), so every link in a reply reads as Luke speaking. A long bare URL in it is a 90-character cyan bar that wraps mid-word, which is the part Dean dislikes.
  3. Only some links open anything.
    • A transcript or Inbox link opens in the browser.
    • In the plan's read view, version history and notes, a link is a <span> that opens nothing (markdown-message.tsx: "the renderer opens no arbitrary address"), with the address as a native title.
    • In the editor, openOnClick: false.
  4. No hover or focus state anywhere. A transcript link shows its address nowhere, since it has no title and Electron has no status bar. A plan link's address is a native tooltip.
  5. Bare URLs always print whole. Both renderers autolink them (GFM), and overflow-wrap: anywhere breaks them at any letter.
  6. Version history, Code-tab notes and the Inbox draw a mention as a plain link reading @Rollout, while the plan beside them draws the chip. History and notes pass no link drawer, and the Inbox stands off the plan's page, outside PlanMentions.
  7. An address that is not a web page (a file: link, say) is dotted in transcripts and plain words in the plan.

How polished tools style plain links

  • Vercel (its brand stylesheet): text colour, a 1px underline 3px below in gray-600, which turns currentColor on hover. vercel-brand.css
  • Notion (react-notion-x's copy of its CSS, not Notion's own): text colour, a faint 0.05em bottom border at 0.7 opacity, full on hover over 100ms. Pasting a URL offers "bookmark" (a card) or "mention" (inline, with icon and title). styles.css, help
  • GitHub: accent blue (#0969da / #4493f8), underline 0.2rem below.
    • Since October 2023, links in text are underlined by default, because a link must stand out by more than colour. changelog, github-markdown-css
    • A bare URL prints whole. Only recognised URLs (issues, PRs, commits) shorten, to owner/repo#26 or a short SHA, which is what chips are doing here. docs
  • VS Code, so Cursor: textLink.foreground blue, no underline except on hover or under an accessibility setting. style.css, theme colours
  • Linear: a pasted URL is a link, with embeds for a few providers and "Keep as link" to refuse one. docs
  • Slack: autolinks plain URLs and unfurls them into OpenGraph cards. A link labelled with its own address minus the protocol does not unfurl. docs
  • ChatGPT: citations are pills with a favicon and a cut publisher name; plain links stay plain. teardown (secondary)
  • Claude.ai and Raycast: no citable source for their plain-link CSS. Linear's, ChatGPT's and Claude's text-colour underline is from memory, unverified.

What that adds up to:

  • The modern prose default is the text colour with a thin (1px), offset (about 0.2em) underline of low contrast, which strengthens on hover. Vercel and Notion verifiably do this.
  • Blue survives in developer tools, but with an underline added for accessibility.
  • None of the verified sources puts ↗ on plain links.
  • Shortening is usually semantic: recognised links shorten and the rest print whole. Rich previews are opt-in cards.
  • Favicons belong to citations and mentions, not to plain links.

(a) Quiet underline

Text colour, a 1px underline 0.24em below the words at 32% of the text's own colour, which goes full strength under the pointer or the keyboard. Every renderer gets it, and a bare URL still prints whole. This is what Vercel's and Notion's prose links do.

(c) Quiet underline + short bare URLs The pick

(a)'s look. Where a link's words are its own address, they shorten to domain/path (a middle step folds to …, a long last step is cut, the #fragment drops) and wear a small ↗, which says the link leaves Luke, as a chip's press stays in it. The full address shows in the window's tooltip. A [label](url) link is not shortened. In the editor the address is the text being edited, so it stays whole.

Pick: (c), and what building it takes

Why (c).

  • It fixes what Dean dislikes: the raw 90-character cyan URL. The cyan goes and so does the length, and the full address is one hover away instead of nowhere.
  • The quiet underline sits best beside a chip. A chip is a filled pill with a leading glyph at medium weight. A text-colour underline has no fill, no colour and nothing in front, so nobody takes one for the other, and it does not shout over the words around it.
  • It is the verified modern default (Vercel, Notion), and it underlines, so it does not rely on colour alone.
  • The ↗ marks the one difference that matters: a chip opens in Luke, a plain link leaves it. It only goes on a shortened address, where it also says the words are a link's.

The alternatives:

  • (a) is the fallback if Dean wants nothing shortened. The build is (c) without the helper.
  • (b) tells a link by colour alone.
  • (d) puts a third pill on the line next to chips and skills. It sits close to a gone chip's outline. Real favicons need main to fetch and cache them, because the window refuses to request images.

How the short address is made

The host loses its www., then the path follows. A short query is kept and the #fragment is dropped. Over 44 characters, the middle steps fold to … and a long last step is cut. The address shortens only when a link's words are its own address. A [label](url) link keeps its label.

Build size: about one small PR

  1. One CSS rule (.text-link in markdown.css, its hover, and the ↗'s size). It replaces .agent-link, .markdown-link and .plan-document-text a. TipTap's link mark gets HTMLAttributes: { class: "text-link" }.
  2. One helper, linkFace(href, words), in packages/ui. It is DOM-free and used by both TranscriptLink (Streamdown) and plainLink (react-markdown). It answers the short address when the words are the address, and the label otherwise. It is tested through its export over the table above.
  3. The address on hover through the window's own Tooltip rather than a native title, on both renderers.
  4. Version history and Code-tab notes get the plan's link drawer, so a mention there is a chip, not @Rollout underlined. The Inbox's mentions are worker 299's to settle.

For Dean to decide, apart from the style: should a plain link in the plan's read view, version history and notes open in the browser, as a transcript's does? Today it opens nothing. The opener already exists (useOpenLink); the read view's link would stop its click there, as a chip does, so the click does not open the section's editor. It is a few lines, and the build can carry it or leave it.
