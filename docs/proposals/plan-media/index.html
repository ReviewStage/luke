Images in plans

Decided by Dean on 2026-10-15: v1 as proposed, images and Mermaid, with the twelve decisions as recommended, no labels on history's picture changes, and the uploading state redesigned (below). Dean asked: "I want to support images (and maybe other types?) in plans." This show draws the recommended v1, images plus Mermaid diagrams, in main's real components. Each frame is main's compiled desktop stylesheet, light and dark, over the DOM that PlanBody, VersionView, the TipTap plan editor and AttachmentViewer drew. The proposal is patched into their sources as the show is bundled. The pictures are synthetic, went through the real encodeImage, and every frame was captured under the window's own Content Security Policy. The written proposal is docs/proposals/plan-media.md.

The recommendation in one breath.

  • Paste, drop, or Insert image in the plan editor. The picture is re-encoded on the Mac to at most 1.5 MB, uploaded at once, and stored in a plan_attachment table beside the plan, as the Inbox's pictures are.
  • The text holds ![alt text](https://tryluke.dev/acme/plan/<id>/files/<file> "caption").
  • Only the plan's readers can fetch the bytes. The bytes never ride the plan read, and the window caches them by id.
  • The read view draws the picture with its caption, the viewer enlarges it, and version history marks a picture written in or struck out in green and red.
  • Agents read the alt text and can look at a picture with a tool, and an agent can add a screenshot from its sandbox.
  • A mermaid fence draws as its diagram.

Uploading: two options

Dean: "I don't feel like the uploading fits in with our app, let's redesign that." The veil is gone. Both options keep the picture at its final size, so nothing moves when the upload lands, and both use the window's own pieces. Until the upload answers, the picture writes nothing to the text.

Today

The read view draws an image's alt text alone (markdown-message.tsx:288). The editor round-trips the line, and nothing pastes or drops a picture. Below is main today, unpatched, drawing the same text as the frames that follow.

A bug on main, found building this show: TipTap's Paragraph turns a paragraph holding only an image into a block-level image, but main configures Image as inline. A plan with an image on its own line therefore opens as an invalid document, and the first edit that touches it throws. PR 1 fixes it before any upload exists.

Writing a picture

Selected

Selecting a picture shows its tools: Alt text, Caption, Enlarge, Delete. Backspace removes it and ⌘Z brings it back.

Alt text

Alt text describes the picture for anyone who cannot see it, and for agents, which read the plan as words. The caption is the Markdown title, drawn under the picture.

The line the editor saves. Opened in a browser, the address lands on the Open in Luke page, which reveals nothing. Its bytes are served only to the plan's readers, on their own sign-in.

The viewer

Version history

A picture written in

A picture is one token to the diff. Written in, it wears the green edge, as the words written in with it wear the green wash.

A picture replaced

The struck picture is dimmed behind a red dashed edge, and the new one follows on the green. No label is added: the red and green say it, as they do for words. Restoring either version restores its picture, since bytes live as long as the plan.

States

Loading, unavailable, from outside Luke

While its bytes are read, a picture is a quiet box. One this reader cannot reach, such as a picture copied from another workspace's plan, shows its alt text. A picture from outside Luke is never fetched, because the CSP refuses it and fetching tells the host who reads the plan, so it is a link with an image glyph.

Agents and Luke

A screenshot a coding agent added

edit_plan gains an image note naming a file in the agent's sandbox. The service reads it through the Inbox's intake, stores it as the plan's, and writes its line. The section's byline names the agent, as for any agent save.

  • Seeing pictures: the brief carries each picture's line, so an agent reads its alt text and caption. look_at_plan_file hands it the picture when it decides it needs one, as look_at_board does for Luke. Pictures are not vision input on every brief.
  • The notetaker keeps pictures and never adds them. A correction that would drop a picture's line is refused, as one that drops a mention is.

Mermaid diagrams v1

Read view

A mermaid fence draws as its diagram. Its code is still the text, which agents read and write as they already do on GitHub.

Editor

The fence stays code while editing, with its diagram previewed under it.

Measured building this show:

  • Size. A flowchart or sequence diagram loads ~228 KB gzipped on first use, as its own lazy ESM entry. Every diagram type would be ~950 KB.
  • The CSP. Mermaid's <style> is refused by style-src 'self', so it is drawn as an <img> of its SVG.
  • Labels. Mermaid measures labels in the page, so its theme CSS is adopted as a constructable stylesheet first.

These diagrams were drawn exactly that way, under the window's policy.

Decisions for Dean

  1. Scope of v1. Recommended: images plus Mermaid. Files, link cards and video later.
  2. Storage. Recommended: a plan_attachment table in Postgres, as inbox_attachment is. There is no object store to reuse, and only video would justify adding one.
  3. The address. Recommended: https://tryluke.dev/<workspace>/plan/<id>/files/<file>, which lands on the Open page in a browser. Not a private scheme, and not inline data:.
  4. Caption and alt text. Recommended: alt text for the description, and the Markdown title for an optional caption.
  5. Who sees pictures. Recommended: exactly the plan's readers, checked on every read, with no public link.
  6. Resizing. Recommended: not in v1.
  7. Pictures from outside Luke. Recommended: never fetched, drawn as a link. Import later.
  8. Orphaned bytes. Recommended: kept while the plan stands, so every version restores. Unsaved uploads are swept after a day.
  9. Agents seeing pictures. Recommended: alt text in the brief plus a look_at_plan_file tool.
  10. Agents adding pictures. Recommended: yes, from a sandbox file. The notetaker never adds them.
  11. Mermaid in v1. Recommended: yes, with a new ~228 KB lazy budget line.
  12. Insert image's place. Recommended: paste, drop, and Insert image in ⌘K and the Edit menu while editing.
