# Who did this: how products draw mixed human / bot / AI / automation authors

Research date: 2026-10-15. Every claim cites a URL. Items marked **(unverified)** are from memory or a third-party source and were not confirmed in official docs.

## 1. Linear

- **Agents are users.** "Each agent has a full user profile and is clearly identified as an app user." Agents can be assigned, @mentioned, and added to teams and projects. https://linear.app/changelog/2025-05-20-linear-for-agents
- **Identity = the app's name and icon.** "The name and icon of your application will be how the agent appears in workspaces where it is installed." Installing with `actor=app` creates a dedicated workspace user. https://linear.app/developers/agents
- **Assignee vs delegate.** "Issues can only be assigned to humans, and only delegated to agents." "Any issue involving an agent has both a human assignee and an agent it's been delegated to." https://linear.app/now/our-approach-to-building-the-agent-interaction-sdk. The sidebar shows the agent beneath the human assignee. https://linear.app/changelog/2025-07-30-agent-interaction-guidelines-and-sdk
- **Disclosure principle.** "An agent should always disclose that it's an agent" and "An agent cannot be held accountable", so a human stays responsible. https://linear.app/developers/aig
- **Name collisions** get a number suffix ("Charlie" becomes "Charlie1"). Agent "user pages show issue activity and contributions." Agents cannot sign in or administer. https://linear.app/docs/agents-in-linear
- **Hover card:** it shows online/away/offline presence on comment avatars (https://newsletter.linear.app/issues/linear-changelog-my-issues-online-status-resizable-sidebars-240683), and a 2026 change added a "Guest" badge to the hover cards of guest users (found via Linear changelog search; https://linear.app/changelog/page/3).
- **Profile page:** it lives at `linear.app/<workspace>/profiles/<username>` and lists the issues the user created or was assigned. https://linear.app/docs/adding-and-managing-members
- **Not found in docs:** a specific badge glyph or square shape for agent avatars. In practice an agent shows its app logo as its avatar **(unverified)**.

## 2. Notion

- **API model:** every user has `type` `"person"` or `"bot"`. A bot user carries its owner (a workspace or a user). https://developers.notion.com/reference/user. `created_by` and `last_edited_by` hold user objects, bots included. https://developers.notion.com/changelog/created-by-and-last-edited-by-properties-in-block-page-and-database-objects. A page made from a template through the API records the bot as its creator. https://developers.notion.com/guides/data-apis/creating-pages-from-templates
- **Database properties:** the "Created by" and "Last edited by" properties fill themselves in. https://www.notion.com/help/guides/tips-to-keep-your-teams-notion-pages-up-to-date
- **Agents in history:** the 3.8 release notes say "With agents and people making constant updates, version history has never been more important... highlighted edits, detailed database changes, and attribution." https://www.notion.com/releases. Custom Agents can be @mentioned, and their runs appear in an Activity tab. https://www.notion.com/help/custom-agents. The audit log attributes a page event to the agent and stores the human who triggered it in the event metadata. https://www.notion.com/help/audit-log
- **Hover cards:** these appear on @-mentions, comments, the inbox, and person properties. Clicking the name opens the full profile, which shows "top collaborators", "teamspaces they belong to", and "recent activity in your workspace." Hover cards and profiles exist for members only, and an owner can turn them off. https://www.notion.com/help/people-profiles. Hovering a page-header avatar shows the person's name, email, and when they were last on the page. https://www.notion.com/help/collaborate-with-people
- **Not found:** how an inline Notion AI edit is attributed in history, and the avatar shape for bots or agents.

## 3. Figma

- **Toolbar facepile:** clicking a collaborator's avatar follows them. While following, a border in "the color of the person's avatar" frames the canvas. A presenter's avatar gets a dashed border. https://help.figma.com/hc/en-us/articles/360040322673-Follow-along-with-observation-mode
- **No photo:** Figma shows "a colored circle with your first initial", or the user's Gravatar if they have one. https://help.figma.com/hc/en-us/articles/360041034433-Manage-name-or-avatar
- **Version history:** a named version shows "the name and avatar of the main contributor." Autosaves show only a date and time and are grouped. https://help.figma.com/hc/en-us/articles/360038006754-View-a-file-s-version-history
- **Plugins and widgets:** a plugin's Community page shows its creator, likes, and usage counts. https://help.figma.com/hc/en-us/articles/360038510693-Guide-to-the-Figma-Community
- **Not found:** how Figma AI is attributed as an author.

## 4. GitHub

- **Shape rule (Primer):** "Circle Avatars represent individual people. Square Avatars represent non-human entities, such as bots, AI agents, teams, or organizations." Sizes run from 16 to 64px. Alt text is needed when no name sits beside the avatar. https://primer.style/product/components/avatar
- **AvatarStack:** shows 2 to 4 avatars, and they spread out on hover unless `disableExpand` is set. It takes a `shape` of circle or square. Primer advises against it when there is room to show four or fewer. https://primer.style/product/components/avatar-stack
- **Bot accounts:** "Bot accounts are specific to GitHub Apps." An installation token acts as "@jenkins[bot]". A user token acts as the user. Bots use no seat. https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/differences-between-github-apps-and-oauth-apps. A Bot is "a special type of user which takes actions on behalf of GitHub Apps." https://docs.github.com/en/enterprise-server@3.22/graphql/reference/apps
- **"On behalf of" rendering:** when an app acts for a user, the UI shows "the user's avatar photo along with the app's identicon badge as the author." https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/authenticating-with-a-github-app-on-behalf-of-a-user
- **"bot" pill** next to `name[bot]` in timelines **(unverified, observed)**. A bot's hovercard and links sometimes point to `/name[bot]` rather than `/apps/name`, a known rough edge. https://oss.issuehunt.io/r/sindresorhus/refined-github/issues/2766
- **Copilot coding agent:** "The cloud agent's commits are authored by Copilot, with the human who started the task marked as the co-author." The commits are signed ("Verified"). https://docs.github.com/en/copilot/responsible-use/agents. Each commit carries an `Agent-Logs-Url` trailer that links to the session. https://github.blog/changelog/2026-03-20-trace-any-copilot-coding-agent-commit-to-its-session-logs/. The PR dashboard shows the author as "username with Copilot", and `author:@me` matches PRs that Copilot opened for you. https://github.blog/changelog/2026-06-18-copilot-authored-pull-requests-now-included-in-author-searches/. The person who assigned Copilot can't approve its PR toward the required approvals. https://docs.github.com/en/copilot/how-tos/use-copilot-agents/coding-agent/review-copilot-prs
- **Hovercard:** a larger avatar, profile info, and context about the viewer's relationship to the person: shared teams, code owner, first-time contributor. It appears on avatars and "most places you see their username." https://github.blog/news-insights/the-library/user-hovercards/. The API returns a `contexts[]` list of `{message, octicon}` and takes a subject of organization, repository, issue, or pull request. https://docs.github.com/en/rest/users/users#get-contextual-information-for-a-user
- **Profile page:** a README, photo, name, pronouns, and bio. Also status, pinned repositories, the contribution graph, achievements, the activity feed, followers, and organizations. https://docs.github.com/en/account-and-profile/concepts/personal-profile

## 5. Google Docs

- **"Last edit":** hovering the Last edit icon shows "who was the last person to update the file and when." A blue dot means it changed since you last viewed it. Version history names who made each change, and "Show editors" works on a selection. https://support.google.com/docs/answer/190843
- **No photo:** since 2015–16, an initial on a coloured circle (the given-name initial, or the whole name if it is two characters). https://workspaceupdates.googleblog.com/2016/02/change-to-default-avatar-for-google.html
- **Unknown viewers** appear as "anonymous animals". https://techcrunch.com/2013/04/25/google-anonymous-animals. 13 more animals were added in 2019, on pastel backgrounds. https://9to5google.com/2019/05/17/google-docs-endangered-animals/
- **Colour per editor** in version history **(unverified in official docs)**. **Gemini edit attribution: not found.**

## 6. Bonus

- **Atlassian (the strongest precedent for a three-way split):** "circle avatars to represent a person", "hexagon avatars to represent an agent entity, such as Rovodev or other AI-powered entities", "square avatars to represent other entities, such as a project, repository or space". A presence dot sits bottom left and a status icon top right. https://atlassian.design/components/avatar/usage. AvatarGroup stacks at most 5 avatars and adds a "+N" avatar whose hover dropdown lists the hidden names. The grid form shows 11 plus "+N". https://atlassian.design/components/avatar-group/usage
- **Slack:** a bot posts with the app's icon and bot name. https://api.slack.com/methods/chat.postMessage. Slack's advice is to "think of the app's name as its display name." https://docs.slack.dev/changelog/2017-09-the-one-about-usernames/. Clicking an app opens its App Home, with Home, Messages, and About tabs. https://docs.slack.dev/surfaces/app-home/. A person's profile holds name, photo, title, status, local time, pronouns, and Do Not Disturb state. https://slack.com/help/articles/4417558556691-Manage-profile-details-for-Slack-Connect. The grey "APP" pill beside an app's name **(unverified, observed)**. Developers report a newer "Added by [App]" label. https://trailhead.salesforce.com/trailblazer-community/topics/slackdevelopers
- **Cursor:** cloud agents commit as "Cursor Agent", with the person who triggered the run in a `Co-authored-by:` trailer, according to staff on the forum. https://forum.cursor.com/t/disable-auto-co-authored-by-cursor-on-agent-commits-or-make-it-opt-in/168258
- **Devin:** PRs are opened by `devin-ai-integration[bot]`, with a "Requested by: @user" line in the body (seen in a third-party repo). https://github.com/flightcontrolhq/modules/pull/84
- **Vercel:** the Vercel bot comments on PRs. Deployments are gated on the commit author having team access, and a Copilot noreply author was rejected. https://vercel.com/docs/git/vercel-for-github, https://community.vercel.com/t/error-git-author-must-have-access-on-vercel-to-create-deployments/21847

## Cross-product patterns

1. **Shape encodes kind.** People are round everywhere. Non-humans are square in Primer (bots, AI agents, orgs, teams) and in Atlassian (projects, repositories). Atlassian alone gives AI agents a third shape, the hexagon. Linear and Notion keep agents in the same slots as people (assignee menu, people property) and tell them apart by label, not by documented shape.
2. **Badges are a second channel on top of shape.** GitHub has the `[bot]` suffix (plus the bot pill), Slack the APP pill, Linear "app user" and "Guest", and Atlassian a status icon top right with presence bottom left. GitHub's "on behalf of" pattern is the human's avatar with the app's identicon as a corner badge.
3. **Two-party naming when an agent works for a human.** GitHub uses "username with Copilot" with Copilot as commit author and the human as co-author. Cursor uses "Cursor Agent" plus `Co-authored-by`, and Devin a `[bot]` author plus "Requested by". Linear splits roles: a human assignee and an agent delegate. Notion's audit log records the agent as actor and the triggering human in metadata. The rule that recurs is that the machine is the actor and a named human stays accountable (Linear AIG).
4. **Overflow.** Atlassian shows 5 avatars plus "+N", with the hidden names in a hover dropdown. Primer shows 2 to 4 and spreads them on hover. Figma's toolbar avatars are clickable and lead to follow.
5. **No-photo fallback.** An initial on a coloured circle (Google, Figma). A per-user hue is reused as that person's identity colour: Figma's follow border, Google's anonymous animals.
6. **Hover card holds:** a larger avatar, name, and role or kind badge. Then presence (Linear), relationship context (GitHub: shared team, code owner, first-time contributor), and contact or last-seen details (Notion). A click goes to a profile.
7. **Profile page holds:** identity (photo, name, title, pronouns, local time and status), plus what they did. That means Linear's created and assigned issues, Notion's recent activity, collaborators, and teamspaces, and GitHub's README, pins, contribution graph, and organizations. An app's "profile" is an About or home page instead (Slack App Home, GitHub `/apps/<slug>`). Linear gives agents the same user page as people.
