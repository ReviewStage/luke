Comments on tasks

Comments let people and agents talk about a task's plan without changing it. You select words and press Comment, or press the comment button that shows beside a paragraph. The thread opens beside that passage, the way it does in Notion. Every frame is drawn with the desktop renderer's own tokens and geometry (base.css, desktop.css, planning.css): the type, menus, buttons, actor marks, sidebar, and plan layout. Use the toggle to switch between dark and light. The prototype in the first section responds to your clicks. The frames after it each show one state, because a picture can't show a hover.

Prototype

Things to try: hover a paragraph and press the comment button on its right; select some words in the plan and press Comment; click a highlighted passage; post a reply; open Send to and pick Luke, who answers a moment later; open a comment's ⋯ and pick Copy link; press ✓ to resolve; open Comments in the summary and reopen a resolved thread. Delete the passage with the strikethrough button above the frame, then use ⌘Z and ⇧⌘Z (or the buttons).

The thread

A thread is a list of comments, each with its writer's mark, name, and time. A person gets their face. Luke gets his face in his blue. A coding agent gets its harness mark and the name its tab shows. These are the same marks the transcript and plan bylines use (ActorRef, 16px). A thread you aren't looking at shows its first comment and a reply count. The thread you open is drawn as a popover, using the menu tokens.

Starting a thread

There are two ways in, and both put the thread beside its passage. A comment's draft is a plain field, so ⌘Z and ⇧⌘Z undo and redo the draft's words and never reach the plan.

Send to: asking Luke or an agent

Posting never starts work. To get an answer, open Send to in the thread's reply field and pick who reads it. Luke comes first, for reasoning about the plan, and below him the task's coding agents by name, for changing code. Each agent is drawn the way its tab is: harness mark, name, and model as the detail. The menu is the app's searchable menu (searchable-menu.tsx). The whole thread is the request, and the plan's text is its context. The agent replies in the same thread. It doesn't edit the plan or fix everything discussed unless the thread asks it to.

Where a thread sits

The plan's column is 720px, set by --reading-width. A thread needs 288px next to it plus a 48px gap. When the column has that room, threads sit in the margin, each level with the top of its passage, and a lower thread moves down if two would overlap. When it doesn't, the plan stays centred and a count button stands where the section ⋯ hangs. The threads behave the same either way.

Resolve and history

✓ resolves a thread. Its card leaves the margin, using the exit motion, and its highlight leaves the words. The thread is still stored and appears under Resolved in the Comments tab, with who resolved it and when. Reopen brings the card and the highlight back. Any member of the workspace, and any agent on the task, can resolve or reopen, and there is no extra permission. Editing the passage never resolves a thread.

Deleted text, undo and redo

The mark is part of the plan's text, so it moves with its words through every save and merge. If the words are deleted, the thread stays where they were. It keeps the original quote, struck through, and says Original content deleted. It stays open until someone resolves it, and it never reattaches to other text. Undo belongs to the plan's text. Comments, replies, resolving, and reopening are separate actions and aren't in that history.

Links to a comment

Every comment's ⋯ has Copy link, the same item and the same "Link copied" toast that a section's ⋯ uses. Opening the link opens the task, scrolls to the passage, opens the thread, and flashes the comment once. A link to a resolved thread opens the Comments tab on Resolved, with that thread highlighted. Pasted into a message or the plan, the link becomes a mention chip that names the passage's section.

What agents see, and when they act

Agents can read comments at any time for context, but they only reply when someone uses Send to. Internal names such as "Brain" never appear on screen. The thread just says "Luke".

Open questions (my assumptions)

  • Comment on a section heading? Assumed yes. The heading's row gets a comment button before its ⋯, and the thread covers the whole section.
  • Send to with no named agent: assumed the menu shows Luke alone, with no "New coding agent" item. Starting an agent stays with Start.
  • Who can edit or delete a comment: assumed only its writer can edit or delete their own comments. Deleting a whole thread is open to every member, like resolving.
  • Notifications: not in this design. A reply doesn't reach the Inbox. Suggested as a follow-up: replies on threads you started.
  • @mentions inside a comment: the field takes the same @ menu as the plan editor (files, sections, people). Mentioning an agent does not ask it anything; only Send to does.
