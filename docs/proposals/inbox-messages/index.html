Inbox items

An inbox item is a thread, and every message in it is a small document. An agent or a person can post at any point, and every message takes the same Markdown: chips, captioned pictures, code, steps. An agent's message can end with an ask. Replying never answers it: you can talk it over as long as you like. To answer, press one of the ask's answers. That attaches the answer to your reply, which you then send.

thread

A title and its messages

Anyone in the workspace, or the agent, adds to it at any time. It's waiting on you while an ask in it is open.

message

A freeform document

The same Markdown for agents and people: [@chip](url), ![alt](src "caption"), a lone link expanded into its card, - [ ] steps.

ask

Closes an agent's message

Decide, do, or answer. It stays open through any number of replies. At most one is open per thread; a newer one replaces it. The reply that answers it carries a stamp: Approved

What changes from today

  • The thread is the item. Today's question, answer and messages are three separate kinds of thing. Now they're all messages in one list, in the order they were written.
  • Every message is Markdown in the plan's dialect, an agent's or a person's: chips, captioned pictures, side-by-side pairs, code from a line link, steps. No more block list, link block or image list.
  • An ask belongs to a message. An agent can ask again later in the same thread instead of reposting the item, and a newer ask replaces the open one.
  • An answer is a reply. It's a normal message with a stamp (Approved, Chose 7 days, Done) and whatever you wrote, pasted or linked.
  • Replying never answers. The reply box only replies. The ask's answers sit in the ask; pressing one attaches it to your reply as a stamp you can remove, and the send button takes its name (Approve ⌘↩).
  • One status: waiting on you while an ask is open, shown as the orange dot on the row and in the thread's line under the title.

The agent's tools, sketched

// One tool to write: the first post under a key opens the
// thread; a later one adds a message to it.

  key: string,
  title?: string,           // on the first post
  body: string,             // Markdown; pictures by sandbox path
  ask?:
    | { type: "decide", options, multiple?, recommended? }
    | { type: "do", steps: string[] }
    | { type: "answer", fields?: Field[] },  // a field may name a recommended value
  waits?: boolean,          // was needsReply
})

What a message is

{
  id, author: agent | member,
  body: string,             // the same for both
  files?: File[],           // pasted pictures, drawn inline
  ask?: Ask,                // agent messages
  answers?: {               // a reply that answers the open ask
    ask: messageId,
    reply: chose | approved | declined | done
         | not-done | submitted | answered,
    choices?, values?, steps?
  },
  createdAt,
}

This keeps today's routing: a reply to an ask that waits reaches the agent as an "Inbox answer"; any other reply reaches it as an "Inbox message".

Recommended values on fields

  • Every field may name a recommended value, as a choice already names a recommended option: { type: "number", label: "Hours before expiry", recommended: 24 }.
  • It's shown, never filled in, following the decision in inbox-recommended.md that an answer is a deliberate press. A text or number field shows the value in muted italics with Use ⇥, and Tab in the empty field takes it. A select's option and a yes/no carry a quiet "recommended" tag.
  • Submit counts only what you filled in or took. A required field left on its suggestion still needs a press.

Open questions

Can a person make an ask too?For example, Dean asks Charles to approve. As drawn, only agents ask, and people reply.
Can anyone answer, or only the person who started the agent?As drawn, anyone in the workspace can answer, as today, and the stamp says who.
Can an agent edit a message it already posted?As drawn, it only adds messages, so the thread is the history. Today, reposting replaces the item in place.

An inbox item today is a title, up to 8 blocks, and exactly one response. Each block is a full-width row drawn in the order the agent sent it; the response decides which controls sit under the blocks, and every item is answered through the composer docked at the foot of the pane. Everything below is drawn with the app's own tokens, after inbox-pane.tsx, inbox-list.tsx and desktop.css.
